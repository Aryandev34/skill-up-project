SKILL UP (Quiz_E_learning) — Project Creation + Code-Level & UI Explanation
================================================================================

SECTION 1 — BRIEF (what it is + how it was created)
--------------------------------------------------------------------------------
What this project is
- Skill Up is a Django e-learning quiz website.
- Users can sign up / log in, choose a language (track), pick a difficulty
  (Low/Medium/High), answer 10 MCQ questions, and then see results.
- Each quiz submission is stored as a quiz attempt in SQLite (score + date).

How it was created (high-level build steps)
- Created a Django project named `skillup` (Django 5.0.4) and an app named `quiz`.
- Enabled Django built-ins: authentication, sessions, messages, CSRF protection.
- Designed 3 database models: Language (track), Question (MCQs), QuizAttempt (history).
- Built the flow using Django’s pattern: URLs → Views → Templates (HTML) + Static (CSS).
- Styled the UI with custom CSS in `quiz/static/quiz/css/skillup.css`, plus:
  - Google Font: Plus Jakarta Sans
  - Font Awesome icons
- Added a seeding command `python manage.py seed_skillup` to insert demo tracks and
  enough questions to run 10-question quizzes.

How to run (quick)
- From the folder that contains `manage.py`:
  - python -m venv .venv
  - .venv\Scripts\activate
  - pip install -r requirements.txt
  - python manage.py migrate
  - python manage.py seed_skillup
  - python manage.py runserver
- Open http://127.0.0.1:8000/


SECTION 2 — DETAILED (code-level + UI: what each part does)
--------------------------------------------------------------------------------

2.1) Project structure (main folders/files)
- manage.py
  - Entry point for Django commands (runserver, migrate, seed command).

- skillup/ (project package)
  - settings.py
    - INSTALLED_APPS includes `quiz`
    - SQLite database: db.sqlite3
    - Auth redirects:
      LOGIN_URL = quiz:login
      LOGIN_REDIRECT_URL = quiz:dashboard
      LOGOUT_REDIRECT_URL = quiz:landing
  - urls.py
    - /admin/ → Django Admin
    - / → includes quiz.urls (the whole website is served from the quiz app)

- quiz/ (main app)
  - models.py: database tables
  - views.py: request/response logic (landing, signup, login/logout, dashboard, quiz)
  - urls.py: app routes (maps URLs to views)
  - forms.py: SignUpForm styling + validation using Django UserCreationForm
  - templates/: HTML pages (Django Templates)
  - static/: CSS/images (served by Django static files)
  - management/commands/seed_skillup.py: demo content loader


2.2) Database layer (models.py)
These are the core database tables (ORM models):

1) Language
- Fields:
  - name, slug (unique), icon_class (Font Awesome class), blurb, order
- Behavior:
  - auto-generates slug from name when not provided (slugify)
- Used by the UI:
  - landing page (guest preview) shows all languages
  - dashboard lists languages to practice

2) Question
- Fields:
  - language (FK → Language)
  - difficulty: low / med / high (TextChoices + db_index)
  - text
  - choices: choice_a, choice_b, choice_c, choice_d
  - correct: one of a/b/c/d
- Helper:
  - correct_text(): returns the correct option’s text for results display

3) QuizAttempt
- Fields:
  - user (FK → auth user)
  - language (FK)
  - difficulty
  - score, total (default 10)
  - created_at (timestamp)
- Purpose:
  - keeps history / progress (each submission becomes one row)


2.3) Routing layer (quiz/urls.py + skillup/urls.py)
Root URLs (`skillup/urls.py`)
- /admin/ → Django admin UI
- / → quiz.urls

App URLs (`quiz/urls.py`)
- /                → landing (guest homepage)
- /signup/          → signup
- /login/           → SkillUpLoginView (Django auth)
- /logout/          → SkillUpLogoutView (Django auth)
- /dashboard/       → dashboard (login required)
- /language/<slug>/ → select_level (login required)
- /language/<slug>/quiz/<difficulty>/ → take_quiz (login required, GET+POST)


2.4) View layer (quiz/views.py) — request → logic → template
Constants used
- QUIZ_SIZE = 10
- SESSION_QUIZ_KEY = "skillup_quiz"

A) landing(request)
- If user is already logged in → redirect to dashboard.
- Else loads languages and renders `quiz/landing.html`.
UI impact:
- Visitors see a modern landing UI with a hero section and a “tracks” preview grid.

B) signup(request)
- If logged in → redirect to dashboard.
- GET: show SignUpForm
- POST: validate form → create user → login(user) → show success message → redirect dashboard
UI impact:
- Split layout (left marketing panel + right form) from templates.

C) SkillUpLoginView / SkillUpLogoutView
- Uses Django built-in auth views but with custom template and redirect behavior.
- Login template: `templates/registration/login.html`
- Logout: redirects to landing
UI impact:
- Login page has the same split layout styling as signup.

D) dashboard(request) [@login_required]
- Loads all languages + annotated question count (Count("questions")).
- Renders `quiz/dashboard.html`.
UI impact:
- Grid of language cards; each goes to select_level for that language.

E) select_level(request, slug) [@login_required]
- Fetch Language by slug.
- Counts how many questions exist per difficulty for that language.
- Creates a list of “levels” where each level has:
  - label/value, number of questions, and ready=True/False
  - ready is True when count >= QUIZ_SIZE (10)
- Renders `quiz/select_level.html`.
UI impact:
- Shows 3 cards (Low/Medium/High). If not enough questions, button is disabled.

F) take_quiz(request, slug, difficulty) [@login_required, GET+POST]
GET (start a new attempt)
- Validates difficulty in {low, med, high}.
- Builds a pool of question IDs matching (language, difficulty).
- If pool < 10 → shows error message and redirects back to select_level.
- Else:
  - random.sample() chooses 10 ids
  - stores them in session under SESSION_QUIZ_KEY:
    { slug, difficulty, question_ids }
  - loads the Question rows and renders `quiz/take_quiz.html`.
UI impact:
- Renders 10 question “cards” with radio options.
- Includes a right sidebar with “answered count” + progress bar.

POST (submit answers)
- Reads session data and checks it matches the current (slug, difficulty).
- Loads the exact questions from IDs in session.
- For each question:
  - reads POST field name `q_<id>`
  - compares with `question.correct`
  - increments score and builds per-question details
- Writes a QuizAttempt row to DB (user, language, difficulty, score, total=10)
- Clears the session quiz key (attempt is finished)
- Renders `quiz/results.html` with:
  - score/total, percent, difficulty_label, and details list
UI impact:
- Shows a circular score ring and a “Review” list where each item is green/red.

Important code-level design choices (why it works reliably)
- Session stores only the selected question IDs so the quiz stays consistent
  between GET and POST (users can’t get a new random set on submit).
- CSRF is enabled by default and templates include `{% csrf_token %}`.
- `@login_required` protects practice pages; guests can only see landing/signup/login.

Key pages:

- signup: `quiz/templates/quiz/signup.html`
  - Split layout with marketing panel + form

  - Split layout + custom inputs
- dashboard: `quiz/templates/quiz/dashboard.html`

Reusable UI piece:

  - Custom “Skill up” brand mark, used in nav and auth pages


2.6) Styling (quiz/static/quiz/css/skillup.css)
UI system highlights
- Uses CSS variables (colors, radius, shadows, fonts) under `:root`.
- Creates consistent components:
  - `.su-btn` (primary/outline/sun/dark/ghost)
  - `.su-shell` layout wrapper
  - `.su-grid-skills` / `.su-grid-pick` responsive grids
  - `.su-level-grid` cards for difficulty
  - `.su-q-card` + `.su-choice` for quiz questions
  - `.su-sidebar` with sticky positioning
  - `.su-result-ring` using conic-gradient for score visualization
- Mobile responsiveness handled with media queries (grid columns collapse).


2.7) Demo data seeding (quiz/management/commands/seed_skillup.py)
What it does
- Deletes existing Language and Question rows.
- Inserts 5 languages (Python, Java, JavaScript, SQL, React)
  with:
  - slug + icon_class + blurb + order
- Inserts multiple question sets per difficulty:
  - LOW_*, MED_*, HIGH_* arrays
Why it matters
- Your “ready” logic requires at least 10 questions per difficulty to allow quiz start.
- Seeding ensures the teacher demo always has enough questions for a full run.
